## 1. Як запустити сервер

1. Відкрийте термінал у кореневій папці проєкту (`less7`).
2. Встановіть необхідні бібліотеки (достатньо одного разу):
   ```bash
   npm install
   ```
3. Запустіть сервер:
   ```bash
   npm start
   ```
4. У консолі ви побачите повідомлення про успішний старт:
   ```
   ========================================
   🚀 Сервер успішно запущено: http://localhost:3000 (або 3001)
   ========================================
   ```
   *(Примітка: сервер оснащений захистом від конфлікту портів — якщо порт 3000 зайнятий, він автоматично обере вільний порт 3001 без аварійного завершення).*
5. Відкрийте браузер за вказаною адресою: **`http://localhost:3000`** (або `3001`).

## 2. Демонстрація основних операцій через інтерфейс

Під час захисту продемонструйте викладачу виконання наступних дій:
1. **Створення фільму (Create)**:
   - Заповніть форму: Назва («Матриця»), Жанри («Action, Sci-Fi»), Рейтинг («8.7»), Рік («1999»), Статус («Переглянуто»).
   - Натисніть кнопку **«Зберегти»**.
   - Зверніть увагу: кнопка тимчасово блокується з написом *«Збереження...»*, після чого з'являється зелений банер успіху, а фільм додається у таблицю.
2. **Фільтрація та пошук (Filter & Search)**:
   - У полі пошуку введіть «Матриця» — таблиця миттєво відфільтрує записи.
   - Оберіть статус «Переглянуто» або конкретний жанр у випадаючих списках.
3. **Редагування (Update)**:
   - Натисніть кнопку **«Редагувати»** біля будь-якого фільму. Дані підтягнуться у форму.
   - Змініть рейтинг (наприклад, з 8.7 на 9.5) і натисніть «Зберегти зміни».
4. **Видалення (Delete)**:
   - Натисніть **«Видалити»** біля фільму.
   - Підтвердіть дію у спливаючому вікні `confirm()`. Запис видалиться, з'явиться сповіщення.
5. **Рекомендації та зовнішнє API (Special Feature)**:
   - Натисніть **«✨ Отримати рекомендації»**. Сервер визначить ваш улюблений жанр і завантажить топові фільми з TVMaze.
   - Натисніть **«+ Додати»**, щоб зберегти рекомендований фільм у свою колекцію.

## 3. Збереження даних після перезавантаження (Persistence)

1. Створіть новий фільм або змініть існуючий через вебінтерфейс.
2. Натисніть клавішу **F5** (перезавантаження сторінки) або повністю закрийте вкладку браузера.
3. Відкрийте сторінку знову — **всі дані залишаються на місці**.
4. Пояснення для викладача:
   > *"Frontend не використовує LocalStorage або Cookie для збереження списку. Кожна дія надсилає HTTP-запит до нашого Node.js API, який потокобезпечно записує зміни у файл `data/data.json` на сервері через Promise Mutex чергу."*

## 5. Пояснення однієї функції Frontend

**Функція `fetchJSON(url, options)` з [`public/script.js`](file:///c:/Users/asusz/WebstormProjects/less7/public/script.js):**

```javascript
async function fetchJSON(url, options) {
    let response = await fetch(url, options);

    if (response.status === 204) {
        return null;
    }

    let data;
    try {
        data = await response.json();
    } catch {
        throw new Error("Некоректна відповідь сервера (не JSON)");
    }

    if (!response.ok) {
        throw new Error(data.error || "Помилка при зверненні до сервера");
    }

    return data;
}
```

**Як пояснити на захисті:**
> *«Це універсальна функція-обгортка над стандартним браузерним `fetch`. Вона вирішує три важливі задачі:*
> 1. *Коректно обробляє статус **204 No Content** (наприклад, при DELETE-запиті), коли у відповіді немає тіла, запобігаючи помилці парсингу порожнього рядка як JSON.*
> 2. *Безпечно розбирає JSON через блок `try...catch`.*
> 3. *Перевіряє властивість `response.ok`. Якщо сервер повернув статус помилки (400, 404, 500, 502), функція автоматично зчитує повідомлення `data.error` від бекенду і викидає JavaScript `Error`, який потім ловиться у блоці `catch` та показується користувачеві у вигляді червоного банера.»*

## 6. Пояснення одного route Backend

**Маршрут створення фільму `POST /api/movies` у [`routes/routes.js`](file:///c:/Users/asusz/WebstormProjects/less7/routes/routes.js) та [`services/service.js`](file:///c:/Users/asusz/WebstormProjects/less7/services/service.js):**

```javascript
// routes/routes.js
router.post('/movies', asyncHandler(async (req, res) => {
  const movie = await movieService.createMovie(req.body);
  res.status(201).json({
    success: true,
    data: movie,
  });
}));

// services/service.js
async function createMovie(body) {
  const payloadToValidate = { ...body };
  delete payloadToValidate.id; // Забороняємо клієнту самому задавати id

  const result = validateMovie(payloadToValidate);
  if (result.error) {
    throw createHttpError(400, result.error);
  }

  return repository.create(result.movie);
}
```

**Як пояснити на захисті:**
> *«Маршрут обробляє HTTP POST запит на створення нової сутності:*
> 1. *Обгортка `asyncHandler` перехоплює будь-які помилки й направляє їх у централізований Express middleware.*
> 2. *У сервісному шарі з тіла запиту примусово видаляється поле `id`, щоб клієнт не міг підробити унікальний ідентифікатор.*
> 3. *Викликається функція `validateMovie`, яка перевіряє наявність полів, діапазони року (1888–2100) та рейтингу (0–10).*
> 4. *Якщо є помилки — повертається статус **400 Bad Request**.*
> 5. *Якщо дані валідні — репозиторій генерує надійний UUID через `crypto.randomUUID()` і потокобезпечно додає запис у `data/data.json`, повертаючи клієнту статус **201 Created**.»*

## 7. Помилка, яку допустив Antigravity під час розробки

**Опис ситуації:**
Під час першої реалізації функції отримання рекомендацій (`GET /api/movies/recommendations`) Antigravity робив текстовий пошук у зовнішньому API TVMaze:
`https://api.tvmaze.com/search/shows?q=Action`

**У чому полягала помилка:**
Замість фільтрації за категорією жанру «Action», TVMaze виконав пошук за словом у назві. У результаті користувачу рекомендувалися абсолютно невідомі передачі, у назві яких випадково було слово «Action» (*«Action Team»*, *«Action Sports»* із рейтингом 0), а також поверталися серіали, які користувач уже раніше додав до себе в список.

**Як це було виявлено та виправлено:**
1. Помилку помічено під час ручного тестування ендпоінта у браузері.
2. Було надіслано уточнюючий промпт з описом некоректного результату.
3. Логіку переписано: тепер система завантажує каталог популярних серіалів `/shows`, перевіряє масив жанрів `show.genres` на точний збіг з улюбленим жанром користувача, сортує за спаданням рейтингу та примусово виключає всі фільми, які вже є у файлі `data/data.json`.
